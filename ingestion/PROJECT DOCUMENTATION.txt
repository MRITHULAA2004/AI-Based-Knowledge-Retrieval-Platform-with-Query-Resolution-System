*OVERVIEW OF THE PROJECT*

Finding answers inside large collections of documents is slow, and general-purpose LLMs can hallucinate when 
they lack domain context. This platform solves that by combining:

~ Document ingestion: load, clean and chunk source documents.

~ Embeddings and semantic search: index chunks as vectors so queries match on meaning, not just keywords.

~ Multi-agent query resolution: specialised agents cooperate to interpret the question, retrieve evidence, and compose a grounded answer.

~ Voice interface: ask questions by speaking and hear the answer back.

Key Features

Multi-agent pipeline with separate responsibilities (routing, retrieval, answer generation, voice I/O)
Semantic retrieval over embedded document chunks
Retrieval-augmented answers grounded in your documents, with source references
Voice input and output (speech-to-text and text-to-speech)
Modular ingestion so new document sets can be added without changing agent code
Persistent storage for embeddings and metadata



# **M1.1 — Research & Technical Understanding**

### **1. RAG Architecture**

Retrieval-Augmented Generation (RAG) combines document retrieval with AI response generation. It retrieves relevant information from a knowledge base before generating answers.

**Pipeline:** Document Upload → Text Extraction → Chunking → Embeddings → Vector Database → Semantic Retrieval → Response Generation.

### **2. Multi-Agent Query Resolution**

A multi-agent system uses specialized agents coordinated by an orchestration layer.

**Five proposed agents:**

- **Query Understanding Agent:** Understands user intent.
- **Retrieval Agent:** Finds relevant document information.
- **Response Generation Agent:** Generates context-based answers.
- **Clarification Agent:** Resolves ambiguous queries.
- **Conversation Memory Agent:** Maintains conversation context.

### **3. Embeddings and Vector Search**

- **Embeddings:** Convert text into numerical vectors.
- **Semantic Similarity:** Measures meaning similarity between texts.
- **Chunking:** Divides documents into smaller text segments.
- **Vector Search:** Retrieves relevant chunks based on embedding similarity.

### **4. Web Speech API**

The Web Speech API provides browser-based voice interaction:

- Speech Recognition converts speech into text.
- Speech Synthesis converts text into spoken audio.

### **5. Technology Choices**

- Python and FastAPI — Backend
- Sentence Transformers — Text embeddings
- ChromaDB — Vector storage and search
- HTML, CSS, JavaScript — Frontend
- Web Speech API — Voice interaction
